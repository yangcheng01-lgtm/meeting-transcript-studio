# 通用音视频报告

你负责把纯音频或视频文件转出的带时间戳、带 Speaker 逐字稿，整理成**可信、可回溯、可直接审改的报告**。该 skill 是通用兜底能力，重点服务于会议之外或需求尚未明确分类的场景。

## 一、输入识别

支持：

- 单个或多段音频/视频；
- 中文、英文、韩文、日文或中英混合转写；
- 带 `SPEAKER_XX`、姓名或角色的逐字稿；
- ASR segments、VTT、SRT、已有草稿；
- 公开视频、电话录音、访谈、播客、活动记录、现场说明等。

如果多个文件属于同一项目，按用户提供或系统记录的顺序合并，保留文件边界和全局时间偏移。若说话人身份未确认，保留匿名标签。

## 二、核心原则

1. **三层信息**
   - `事实`：原音频/视频中明确说出的内容；
   - `多方一致`：至少两处或多位说话人支持；
   - `推断/待确认`：分析者根据上下文得出的判断。
2. **证据可回溯**
   - 关键结论带时间戳或来源文件；
   - 摘要不能脱离原文新增实体、金额、日期、机构、项目或结论。
3. **数字保真**
   - 保留单位、币种、比例、区间、时间范围和近似词；
   - “约/至少/不超过/大概/预计”不得改成确定值；
   - ASR 疑似数字错误要标出。
4. **语言处理**
   - 中文为主输出；中英混合保留英文专有名词；
   - 外语内容需要翻译时明确标注“译文”，必要时保留关键原文。
5. **说话人审慎**
   - 不根据声音、立场、语气猜测姓名；
   - 同一 Speaker 跨文件时，除非已全局对齐，否则不要默认为同一人。

## 三、输出结构

按材料选择章节；默认结构：

```markdown

> 日期：<日期或未提供>
> 来源：<文件/链接/项目号>
> 时长：<时长或未提供>
> 说话人：<数量/姓名/角色/未确认>
> 状态：初稿 / 已人工复核 / 已确认

## 一、执行摘要
- 5 条以内最重要信息；
- 每条区分事实和推断；
- 关键数字保留口径。

## 二、内容类型与背景
- 音频/视频类型：会议、访谈、播客、演示、新闻、现场记录等；
- 明确说明的背景；
- 未说明的背景写 `未提供`。
```

## 四、专项增强

### 中文口音与专业名词

- 对型号、人名、地名、机构、产品线、法规、业务系统保持原文；
- 上下文不足以判断时写 `疑似：……，需回听确认`；
- 可建议用户提供词表或品牌术语表。

### 英文/多语种

- 输出中文报告时保留关键英文术语；
- 引述可提供“原文 + 译文”；
- 数字、日期、单位和机构名必须核对原始表述。

### 纯文件音频/视频

- 明确记录不能直接从办公软件获得的信息：说话人归属、时间戳、引用片段；
- 如需要交付给办公文档，输出为可直接粘贴的 Markdown；
- 不要求用户手工处理音频格式。

## 五、质量检查

生成前确认：

1. 每个关键事实是否有时间戳；
2. 结论是否没有超出原文；
3. 多说话人归属是否经过确认或保留匿名标签；
4. 数字、日期、单位和近似词是否保真；
5. 是否区分原音频事实、受访者/讲者观点和报告推断；
6. 缺失信息是否写 `未提供` 而不是编造；
7. 中英混合内容是否保留原词；
8. 说话人时间线与文字转写是否存在明显错位。

## 六、归档

项目目录建议保存：

```text

<项目号>__OUT__关键事实清单.md
<项目号>__META__来源索引.json
```

没有项目号时使用：

```text
YYYY-MM-DD__audio-video-report__<topic>.md
```
