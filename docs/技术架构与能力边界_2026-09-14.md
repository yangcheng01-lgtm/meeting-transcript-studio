# 多听工作台：技术架构、能力边界与迭代方向

**定位**：会议、访谈、培训等音视频，本机完成说话人分离与命名，经公司网关调用 ASR 与大模型，产出带说话人与时间轴的逐字稿及四类报告。全文区分“已验证事实”与“规划判断”。

## 1. 架构图（纯文本）

```text
[导入] 音频 / 视频 / 多文件 / 公开 YouTube
  │  ffmpeg → 16kHz 单声道
  ▼
[说话人分离] pyannote speaker-diarization-3.1（本地推理）
  ▼
[人工命名] Speaker 0/1/2… → 姓名、角色
  ▼
[转写] 按说话人时间块切分 ──► 网关 qwen3-asr：音频分片 → 文本
  │      ▲ 术语词表注入 ASR prompt
  ▼
[逐字稿] 逐片缓存（D 盘）· 失败重试 · 断点续跑
  ▼
[总结] 长稿分段事实抽取 → 汇总（词表注入总结 prompt）
  │  Skill：会议纪要 / 业务访谈洞察 / 培训讲解 / 通用音视频报告
  │  模型：external/glm-5.3-flash（默认）· external/glm-5.3（质量复核）
  ▼
[导出] Markdown / TXT / SRT

数据边界：原始文件、声纹相关产物、逐字稿、报告、缓存 → 全在本机 D 盘
         音频分片与文本 prompt → 仅经公司 OpenAI 兼容网关
         API Key → 仅进程内存，不落盘、不写日志
```

## 2. 端到端数据流

1. 原始文件落 D 盘；
2. 转码 16kHz 单声道（ASR 统一输入规格）；
3. pyannote 产出说话人时间块，落盘；
4. 人工命名，合并为带身份的块列表；
5. 每块音频经网关转写，文本逐片缓存；
6. 合并逐字稿（说话人＋时间戳），可直接出 SRT；
7. 长稿分段限长抽取事实要点，再汇总成稿；
8. 套 Skill 生成报告，导出三种格式。

## 3. 为什么不是“声纹实名识别”

- **合规**：声纹按《个人信息保护法》属敏感生物特征，实名识别须事先采集全员声纹库并单独同意，法律与管理成本高；
- **准确性**：会议远场、串音、设备差异易致声纹误配，“张冠李戴”比“未命名”更伤纪要可信度；
- **可控性**：pyannote 只判断“是否同一人”，不猜身份；人听几秒片段即可命名，可审计、可纠错；
- **结论**：可信度来自人的确认而非黑盒概率。这是有意的产品决策，不是技术妥协。

## 4. 本地与云端数据边界

- **仅本机（D 盘）**：原始音视频、转码音频、说话人时间块等声纹相关中间产物、逐字稿、报告、缓存；
- **经公司网关**：ASR 仅送按说话人切分的音频分片；总结仅送文本与词表；
- **最小传输原则**：只送模型必需的最小单元，一切产物留本机；密钥不落盘。

## 5. 已验证 / 尚未验证

**已验证**（真实样本跑通）：
- 多格式导入、统一转码、公开 YouTube 下载；
- 常规多人内容的说话人分离与人工命名流程；
- 按说话人块转写，术语注入对专有名词纠错（定性有效）；
- 逐片缓存、重试与断点续跑在长音频上可用；
- 四个 Skill 在对应样例产出可用初稿；小时级长稿的抽取-汇总链路。

**尚未验证**（需量化，暂不外承诺）：
- 说话人分离 DER 指标；重叠语音、远场多麦场景；
- ASR 错误率基线与术语增益的量化对比；
- 中英混说、方言与重口音鲁棒性；
- 3 小时以上端到端稳定性与单条成本上限；
- 多用户并发；术语表规模上限（数十条内有效，百条以上未测）。

## 6. 失败恢复与成本控制

- **恢复**：各阶段产物全部落盘，流水线幂等；重试只补失败分片，续跑不重复调用；
- **成本**：ASR 按时长、LLM 按 token。默认 flash 总结，glm-5.3 仅复核；分段抽取限制单次输入长度；术语纠错减少整链返工；缓存命中零成本。杠杆明确、可预算。

## 7. 术语库与 RAG 的渐进路径

- **第 0 步（现状）**：词表直接注入 ASR 与总结 prompt。零基础设施，适合数十条术语；
- **第 1 步**：术语 embedding 化，按当前文档检索 top-k 注入。术语过百或跨团队共享时启动，解决 prompt 膨胀与命中率；
- **第 2 步**：知识库 RAG。历史纪要与访谈洞察入库，支持“上次与该客户谈定了什么”式跨文档问答；
- **GraphRAG 何时需要**：语料达数百份、且出现跨文档多跳关系问题（人—客户—承诺—时间线）时。**何时不需要**：单文档总结、术语查询、小语料——实体抽取与图谱维护成本大于收益。图谱不改善转写质量，只回答关系型问题。

## 8. 三阶段路线

| 阶段 | 范围 | 目标 |
|---|---|---|
| MVP（1–2 天，当前冲刺） | 单机、D 盘、手工词表、四 Skill、三格式导出 | 完成最终回归、固定演示样本并提交视频 |
| 内网 POC（建议 2–4 周） | 内网部署、多用户排队、术语库管理界面、用量统计 | 10–20 名真实用户；WER 抽样基线与总结满意度评分；过安全评审 |
| 生产化（视 POC 数据） | SSO 权限、审计日志、监控告警、成本看板、术语治理、模型路由 | 可承诺的 SLA 与预算模型 |

## 9. 视频演示重点

- **一条真实会议的完整链路**：导入→命名→逐字稿→报告→导出，3–5 分钟，等待镜头剪掉；
- **三个高光**：①聚类＋人工命名，讲“可控”；②术语词表驱动总结层规范名称与“待复核”提示，讲“质量可控”；③长稿分段抽取汇总，讲“规模化”；
- **口径**：强调“人确认、可纠错”，不宣称全自动；断点续跑一句话带过；
- **不讲**：模型原理、配置细节、未验证场景（如远场多人）；
- **主线旁白**：“不猜谁在说话——让你确认谁在说话。”
