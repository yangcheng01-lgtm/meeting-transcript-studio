# 演示视频脚本（3–5 分钟）

> 版本：2026-09-14
> 目标：向评委/团队展示「多听工作台」如何解决多人录音张冠李戴、外语口音识别、纪要不可直接用三个痛点
> 时长：约 4 分钟。全程用真实演示素材（保留典型环节），不念稿堆术语。

## 开场 · 问题（0:00–0:45）

旁白：
- 会议里多人发言，现有工具分不清「谁说了什么」，纪要经常张冠李戴。
- 外语、口音、型号、地名频繁识别错，要反复回听。
- 转写产出没法直接交付，得人工逐句翻听整理。

画面：放一张「混乱录音/错误人名」对比卡片。

---

## 方案（0:45–1:30）

一条链路：
> 导入（音频/视频/YouTube/多文件）→ 声纹区分 Speaker → 人工标人名 → 带时间戳逐字稿 → 选总结 skill → 可审改报告

强调：
- 只呈现必要环节，「多听工作台」默认只显示 导入 → 确认人名 → 导出。
- 公司 qwen3-asr 负责转写，pyannote 负责「谁在说话」。

---

## 现场演示（1:30–3:10）

1. 导入一个真实的会议/访谈片段（比如 60 秒高光）。
2. 自动声纹分离出 2–4 位 Speaker，每个有代表片段和代表文本可试听。
3. 在界面上给每位 Speaker 填人名 / 角色。
4. 导出带时间戳 + 人名的逐字稿。
5. 选择会议纪要 skill，生成结构化报告（决策 / 风险 / 开放问题 / 建议跟进）。

画面建议：
- 录制屏幕操作，配白色光标。
- 每个关键步骤用字幕标注当前处于第几步。

---

## 技术架构（3:10–3:50）

一张架构图：
```
上传文件/YouTube/多文件
        ↓
 pyannote 声纹分离（本地）
        ↓
 qwen3-asr 逐段转写（继承 Speaker 时间边界）
        ↓
 带人名逐字稿
        ↓
 LLM + 总结 skill → 可审改纪要
```

要点：
- pyannote 本地/离线，普通用户无需 HF token。
- qwen3-asr 走公司 API，文字入公司服务。
- 模型可配置 API URL / Key / 模型名，可按需选便宜模型。

---

## 边界与迭代（3:50–4:20）

可说：
- 已验证：中英文转写、多文件拼接、Speaker 试听与标注；公开 YouTube 60 秒片段已完成完整链路。
- 边界：跨录音自动实名声纹识别未实现，需合规评审；私域/会员视频不绕过权限。
- 迭代方向：RAG/词库（long graph 等）识别型号/人名/地名/行业术语，低置信度片段回听。

---

## 路线图（4:20–4:50）

- 当前已完成 ASR 分片重试与缓存续跑；下一步是任务状态持久化（Redis/PostgreSQL/Worker）、多用户 SSO 与权限、审计日志。
- 额度策略：常规生成优先 external/glm-5.3-flash，关键复核用 external/glm-5.3；最多使用剩余额度的 80%，保留 20% 用于补录与重试。
- 结尾：一句话收束——「不是能不能转文字，而是能不能一步到位形成可信、可直接审改的最终产出。」

---

## 演示注意事项

- 用真实手机/文件按钮导入，避免纯贴图。
- 预留一个「翻车兜底」：把最稳定的中文 2-Speaker 高光片段留到最后兜底。
- 全程 3–5 分钟，砍冗余，只保留必要环节。
